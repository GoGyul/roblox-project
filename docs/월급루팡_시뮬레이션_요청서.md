# 월급루팡 시뮬레이션 요청서

Nov 25, 2026 · @고결

## 요청 개요

로블록스 게임 "월급루팡"의 밸런스 수치가 적정한지 확인하려고 아래 7가지 모의 실험(몬테카를로 시뮬레이션)을 요청합니다. 진행 방식은 두 가지입니다. (가) 계산 모형: 이 문서의 규칙과 수치만으로 Python 코드를 작성해 돌립니다. 게임을 실행할 필요가 없습니다. (나) 실제 실행: 로블록스 스튜디오를 실행할 수 있는 환경이라면 게임을 직접 돌려 측정합니다. 이 경우의 절차는 문서 뒤쪽 "스튜디오를 실행할 수 있을 때"에 있습니다. 스튜디오를 쓸 수 있으면 (나)로 가정값을 먼저 실측한 뒤 (가)를 돌리고, 쓸 수 없으면 (가)만 진행해 주세요.

월급루팡은 회사원이 되어 부장님 눈을 피해 딴짓으로 돈을 버는 게임입니다. 하루는 실제 7분이고, 딴짓을 오래 할수록 수입이 늘지만 걸리면 감봉과 경고를 받습니다. 경고 3번이면 해고됩니다.

요청마다 원하는 것은 세 가지입니다.

1. 실험에 쓴 Python 코드 전체 (제가 수치를 바꿔 다시 돌릴 수 있게)
2. 결과 표 (요청마다 정해 둔 형식)
3. "문제 있음 / 문제 없음" 판단과, 문제가 있으면 바꿀 수치 제안

문서에 없는 값이 필요하면 임의로 정하지 말고, 어떤 가정을 넣었는지 결과 맨 위에 적어 주세요. 요청은 서로 독립적이라 하나씩 따로 진행해도 됩니다. 우선순위는 요청 1 → 5 → 2 → 3 순입니다(요청 1의 수입 결과가 나머지의 입력이 됩니다).

## 공통 전제

모든 요청이 같이 쓰는 규칙입니다. 게임 설정 파일에서 그대로 옮긴 값이고, "근사"라고 적힌 것만 단순화한 규칙입니다.

### 하루의 흐름

- 하루 = 실제 420초. 게임 시계로 09:00\~18:00 (게임 1시간 = 약 46.7초).
- 점심 12:00\~13:00 (약 47초): 부장님이 없어 안전하게 딴짓할 수 있음.
- 한 주 = 월\~금 5일. 월요일 아침에 경고가 0으로 초기화됨. 승진한 날에도 경고가 0으로 초기화됨.
- 경고 3번 = 해고 (통장 0원, 직급 강등).

### 의심도 (근사)

- 의심도는 0\~100%. 100%가 되면 적발: 적발 감봉 + 경고 1 + 의심도 0으로 초기화.
- 부장님에게 보이는 동안: 초당 증가 = 들킴 × 오늘의 의심도 속도 × 1/3 (단위 %). 실제 게임에는 두 가지 배율이 더 곱해짐: 폰 게임 중에는 × 0.35, 거리 배율 = 1.5 − 거리/시야범위 (0.5\~1.5로 제한).
- 보이지 않는 동안: 초당 8%씩 감소.
- 오늘의 의심도 속도: 매일 1.0에서 시작, 범위 0.5\~2.0. 월요일 +0.10, 금요일 −0.10, 적발 +0.15, 지각 +0.15, 칼출근 −0.05, 프로젝트 성공 −0.15 / 실패 +0.10, 부장님께 커피 −0.05, 동료 고자질 +0.10.
- 부장님은 사무실을 순찰함. 한 플레이어가 부장님 시야에 들어오는 시간 비율은 실측값이 없으므로, 15% / 25% / 35% 세 가지로 가정해 각각 돌려 주세요.
- 플레이어는 부장님이 보이면 "복귀 시간"이 지난 뒤 일하는 척을 합니다. 반응이 늦을 확률을 유형별로 다르게 둡니다(아래).

### 보너스

- 아슬아슬 보너스: 딴짓하다 일하는 척으로 바꾼 직후 부장님이 보면 200원 × 콤보(최대 5), 하루 5번까지 (하루 최대 3,000원).
- 동료 수다: 주제 하나를 끝내면 500원 + 좋은 맞장구마다 200원. 동료마다 하루 한 번.
- 긴급 프로젝트: 성공하면 경고 −1, 경고가 없으면 3,000원. 확률 추첨 없이 매일 한 번 예약됨(시작 시각 10:00\~10:25 또는 13:05\~15:00 중 무작위). 시작 시각에 사무실 밖이면 들어올 때까지 미뤄지고, 15:10을 넘기거나 부장님이 종일 출장이면 그날은 없음. 제한 시간 100\~110초, 점심·공통 이벤트 중에는 시계가 멈춤. 실패하면 의심도 속도 +0.10(경고는 없음).

## 요청 1: 직급별 하루 수입과 실적 목표 달성률

알고 싶은 것: 각 직급에서 실적 목표가 너무 쉽거나 어렵지 않은가. 이 결과가 다른 요청의 입력이 되므로 가장 먼저 필요합니다.

실험 방법

- 8개 직급 × 4개 플레이어 유형 × 부장님 시야 비율 3가지(15/25/35%) = 96가지 조합, 조합마다 하루를 10,000번.
- 하루를 1초 단위로 진행: 플레이어는 업무 할당량을 채울 만큼은 일하고, 나머지 시간은 유형별 딴짓 비율만큼 딴짓. 점심 47초는 전부 딴짓(위험 없음).
- 유형이 고를 수 있는 행동은 그 직급에서 풀린 것만.
- 적발되면 감봉하고 계속 진행. 그날 경고가 3이 되면 해고로 기록하고 하루 종료.
- 보너스: 아슬아슬은 "부장님이 나타났는데 제때 반응한 횟수"만큼, 수다는 하루 0\~3회 균등, 프로젝트는 매일 한 번 발생한다고 보고(위 "보너스" 참고, 처음 버전의 "하루 40%"는 실제 게임과 달라 정정함) 유형별 성공률(조심 80 / 보통 65 / 욕심 55 / 초보 35%)로 가정.

결과 표 (직급 × 유형, 시야 25% 기준. 15%와 35%는 별도 표)

| 항목 | 의미 |
| --- | --- |
| 하루 실적 평균·중앙값·하위 10%·상위 10% | 원 단위 |
| 실적 ÷ 목표 | 배수 |
| 목표 달성률 | % |
| 하루 평균 적발 횟수 | 회 |
| 하루 실수령액 평균 | 기본급 포함, 감봉 반영 |

판단 기준

- 보통형의 목표 달성률이 80\~95% 사이면 적정. 99% 이상이면 목표가 의미 없고, 60% 미만이면 너무 가혹.
- 초보의 목표 달성률이 사원·주임에서 50% 미만이면 초반 이탈 위험.
- 욕심형의 실수령액이 조심형보다 항상 높으면 "걸려도 이득"이라 적발 감봉이 약한 것.
- 직급이 오를수록 "실적 ÷ 목표"가 계속 커지거나 작아지면 목표 곡선이 수입 배율과 안 맞는 것.

## 요청 2: 승진 속도와 경제 흐름

알고 싶은 것: 인턴에서 이사까지 며칠이 걸리는가, 어느 직급에서 지루하게 오래 머무는가, 돈이 너무 빨리 쌓여 살 것이 없어지지 않는가.

실험 방법

- 요청 1의 하루 모형을 그대로 쓰되, 인턴에서 시작해 이사가 될 때까지(최대 400일) 이어서 진행. 유형마다 2,000명.
- 경고는 주 5일마다 초기화. 해고되면 통장 0원 + 한 직급 강등(경험치는 강등된 직급의 필요 경험치로).
- 돈은 쓰지 않는 경우와, 매일 수입의 30%를 쓰는 경우 두 가지.
- 자격증(선택): 돈으로 사면 경험치를 줌. 컴활 15,000원→경험치 3,000 / 토익 30,000→6,000 / 한국사 50,000→10,000 / 엑셀 80,000→16,000 / PMP 150,000→30,000 / MBA 300,000→60,000. "돈이 모이면 바로 산다"는 전략을 하나 더 돌려 주세요.
- 과장부터는 요청 3의 인사평가 보상이 더해짐(1등: 기본급 2배 성과급 + 기본급 2배 경험치 / 2등: 기본급 1배 / 꼴찌: 기본급 1배 감봉). 순위 확률은 일단 1등 15% / 2등 25% / 3등 40% / 꼴찌 20%로 고정.

결과 표

| 항목 | 형식 |
| --- | --- |
| 직급별 체류 일수 | 유형별 평균·중앙값 |
| 이사 도달까지 총 일수 | 유형별 평균·하위 10%·상위 10% |
| 실제 플레이 시간 환산 | 하루 = 7분 + 대기 약 30초 |
| 해고 횟수 | 유형별 평균 |
| 직급 도달 시점의 통장 잔고 | 돈을 안 쓸 때 |

판단 기준

- 보통형 기준 직급 하나에 머무는 기간이 앞 직급의 2.5배를 넘으면 그 구간이 벽.
- 보통형이 대리(두 번째 회사로 이직하는 시점)까지 실제 1.5\~3시간, 이사까지 15\~30시간이면 적정.
- 초보가 사원·주임에서 해고를 반복해 승진하지 못하는 비율이 20%를 넘으면 문제.
- 과장 이후 통장 잔고가 가장 비싼 물건(요청 7 참고)의 10배를 넘으면 돈의 쓰임새가 부족.

## 요청 3: 인사평가 순위 분포

알고 싶은 것: 과장부터 매주 동료 NPC 3명과 점수로 경쟁하는데, 플레이 방식과 친밀도에 따라 순위가 납득할 만하게 갈리는가. 제가 이미 한 번 돌려 봤으니 독립적으로 구현해 검산해 주세요.

점수 규칙

- 내 하루 점수 = 실적(40) + 근태(20) + 태도(20). 주간 점수 = 하루 점수의 5일 평균 + 동료평가(20).
- 실적: r = (적발 감봉을 빼지 않은 하루 실적) ÷ 목표. r < 1이면 24 × r, r ≥ 1이면 24 + 16 × min(1, (r − 1) ÷ 2.5).
- 근태: 20에서 지각 −6, 점심 지각 −5, 업무 미달 −8.
- 태도: 20에서 적발 1번당 −8, 고자질당한 날 −3. 최소 0.
- 동료평가: 동료 9명이 친밀도에 따라 한 표씩. +40 이상 4점, +20 이상 3.2점, −20 초과 2.3점, −60 초과 1.15점, 그 이하 0점. 평균 × 5.

경쟁자(NPC) 하루 점수 = 기준 + 균등분포(−기복, +기복) + 성장 × (몇 번째 날 − 1), 30\~98로 제한.

| 성격 | 기준 | 기복 | 성장 | 부장님 부재일 보정 | 고자질 성향 |
| --- | --- | --- | --- | --- | --- |
| 성실형 | 82 | 3 | 0 | 0 | 1.0 |
| 견제형 | 80.5 | 5 | 0 | 0 | 1.4 |
| 아부형 | 80.5 | 5 | 0 | −8 | 1.0 |
| 농땡이형 | 73.5 | 11 | 0 | +4 | 0.6 |
| 열정형 | 68.5 | 7 | 2.5 | 0 | 0.5 |

- 사무실 동료 9명(성실 2, 견제 2, 아부 2, 농땡이 2, 열정 1) 중 3명이 매주 무작위로 경쟁자가 됨.
- 경쟁자가 부장님께 혼나면 그날 −3 (하루 50% 확률로 가정). 매일 25% 확률로 경쟁자 한 명이 다른 경쟁자에게 고자질당해 −3. 부장님 부재일은 8%.
- 고자질: 하루 최대 1번. 경쟁자를 무작위 순서로 보며 첫 성공에서 멈춤. 확률 = 친밀도 −60 이하 0.75 / −20 이하 0.5 / +20 미만이고 내가 현재 1\~2등이면 0.3 / 그 밖 0. 여기에 성격의 고자질 성향을 곱하고, 수·목요일은 절반.
- 고자질이 시작돼도 60%만 성공한다고 가정(나머지는 내가 일하는 척을 해서 무산, 그중 절반은 허위 신고로 그 경쟁자 −5). 성공하면 태도 −3, 35% 확률로 적발 1회 추가.
- 친밀도 −60 이하인 경쟁자는 한 주에 한 번, 매일 35% 확률로 내 실적 3점을 가로채 자기 점수에 더함. 친밀도 +85 이상인 경쟁자가 있으면 금요일에 내 점수 +2.

실험 방법

- 요청 1에서 나온 과장 직급의 유형별 하루 실적 분포와 적발 횟수를 입력으로 사용.
- 친밀도 상황 6가지: 전원 0 / 전원 +10\~+45 / 전원 +40\~+90 / 전원 −70\~−10 / 3명만 +50 나머지 0 / 1명만 −40 나머지 +5.
- 유형 4가지 × 친밀도 6가지, 조합마다 10,000주.

결과 표: 조합마다 1등·2등·3등·꼴찌 확률(%), 내 평균 점수, 1등 NPC 평균 점수, 주당 고자질 횟수.

판단 기준

- 친밀도 0인 보통형: 1등 5\~20%, 꼴찌 15\~30%.
- 3명과 친한 보통형: 1등 30\~45%.
- 욕심형이 같은 친밀도의 조심형보다 1등 확률이 높으면 문제.
- 주당 고자질이 3회를 넘는 조합이 있으면 문제(피로도).
- 어떤 조합이든 결과가 99% 이상 한 순위로 고정되면 알려 주세요.

## 요청 4: 친밀도 성장 속도

알고 싶은 것: 동료 친밀도(−100\~+100, 0에서 시작)를 혜택 기준선까지 올리는 데 며칠이 걸리는가, 한 번 나빠진 관계를 회복할 수 있는가.

규칙

- 혜택 기준선: +20, +40, +65, +85. 견제 시작 −20, 앙숙 −60.
- 수다: 동료마다 하루 한 번. 주제 완주 +3, 좋은 맞장구마다 +1(주제당 0\~3회), 눈치 없는 맞장구 −4(수다 종료). 한 동료에게 수다로 오르는 점수는 하루 최대 +8.
- 간식·커피 선물: 동료마다 하루 한 번 +6, 목요일은 +12. 손에 간식을 하나만 들 수 있어 하루에 줄 수 있는 횟수가 제한됨(유형별 하루 1 / 2 / 4회로 가정).
- 업무 도와주기: 하루 35% 확률로 동료 한 명이 요청, 수락하면 +10.
- 신고: 그 동료 −25, 가까이 있던 동료 0\~3명 −5. 고자질하러 가는 동료를 간식으로 붙잡으면 +8.
- +65 이상은 3일 동안 수다도 선물도 없으면 하루 −1.

실험 방법

- 전략 4가지: (가) 한 명에게 집중, (나) 3명에게 분산, (다) 9명 전원에게 고루, (라) 매주 한 번 신고하면서 간식으로 메우기.
- 하루에 수다 가능한 동료 수는 2 / 4 / 6명 세 가지. 좋은 맞장구 확률 60%, 눈치 없는 맞장구 확률 10%.
- 전략마다 60일을 5,000번.

결과 표: 전략별로 +20 / +40 / +65 / +85 도달까지 걸린 일수(평균·중앙값), 30일째와 60일째의 친밀도 분포, 전략 (라)에서 −20 아래로 떨어진 동료 수.

판단 기준

- 한 명 집중 시 +85까지 8\~15일이면 적정. 5일 미만이면 너무 빠르고 25일 초과면 너무 느림.
- 전원을 +40 이상으로 만드는 데 20일 미만이면 요청 3의 "전원과 친하면 거의 항상 1등"이 너무 쉽게 달성되는 것.
- 전략 (라)에서 관계가 계속 악화만 되면 신고의 대가가 과한 것, 완전히 메워지면 대가가 없는 것.

## 요청 5: 의심도 속도와 적발·해고 확률

알고 싶은 것: "오늘의 의심도 속도" 범위를 방금 0.7\~2.5에서 0.5\~2.0으로 바꿨습니다. 이 범위에서 한 번 걸린 사람이 연쇄적으로 걸려 해고되는 일이 얼마나 자주 생기는가.

실험 방법

- 공통 전제의 의심도 규칙으로 하루를 0.25초 단위로 진행.
- 부장님이 시야에 들어오는 것을 "평균 8초 지속되는 방문"으로 모형화: 방문 사이 간격은 시야 비율 15/25/35%가 되도록 지수분포로.
- 플레이어는 방문이 시작되면 "행동의 복귀 시간 + 반응 시간 0.5초" 뒤에 일하는 척으로 전환. 유형별 "반응이 늦을 확률"에 걸리면 추가로 2\~5초 늦음.
- 의심도 속도는 1.0에서 시작하고 요일 보정 적용, 적발될 때마다 +0.15.
- 속도 범위를 세 가지로 비교: 0.7\~2.5(예전) / 0.5\~2.0(지금) / 0.5\~1.5.
- 유형 4 × 시야 3 × 범위 3, 조합마다 한 주(5일)를 5,000번. 경고는 월요일에 0에서 시작해 누적.

결과 표

| 항목 | 형식 |
| --- | --- |
| 하루 평균 적발 횟수 | 요일별 |
| 첫 적발 뒤 같은 날 또 적발될 확률 | % |
| 한 주 안에 해고될 확률 | % |
| 하루 끝 의심도 속도의 분포 | 평균·상위 10% |
| 속도가 상한·하한에 닿은 날의 비율 | % |

판단 기준

- 보통형의 주간 해고 확률 3\~10%면 적정. 초보는 40% 미만이어야 함.
- "첫 적발 뒤 같은 날 재적발"이 첫 적발 확률의 2배를 넘으면 연쇄 붕괴가 심한 것.
- 상한에 닿는 날이 거의 없으면(1% 미만) 상한을 더 낮춰도 되고, 하한에 닿는 날이 30%를 넘으면 하한이 너무 쉽게 닿는 것.

## 요청 6: 하루에 겹치는 이벤트·NPC 상호작용 빈도

알고 싶은 것: 하루 7분 안에 끼어드는 일이 너무 많아 피곤하지 않은가, 서로 겹쳐서 대응할 수 없는 순간이 얼마나 자주 생기는가.

하루에 일어날 수 있는 일 (플레이어가 반응해야 하는 것)

| 종류 | 발생 규칙 | 지속 |
| --- | --- | --- |
| 돌발 이벤트 (소방 훈련·정전·워크숍·감사 등) | 하루 50%, 최대 1개, 9:40 이후 | 30\~90초 |
| 긴급 프로젝트 | 매일 한 번 예약, 15:10 이전에만 시작 | 100\~110초 |
| 부장님 창가 감시 | 45\~80초마다, 예고 3초 + 감시 7초 | 10초 |
| 화상회의 질문 | 화상회의 하는 척 중에만, 약 30초마다 | 5초 |
| 이과장 고자질 | 수·목요일, 대리 이하만 | 순간 |
| 동료 고자질 | 과장부터, 하루 최대 1번, 10:00\~17:00 | 약 15초 |
| 동료 도움 요청 | 하루 35%, 최대 1번, 고자질과 1시간 이상 간격 | 45초 |
| 고양이 방문 | 하루 0\~2번 | 30초 |
| 목요일 회식 | 목요일 퇴근 후 | 별도 |
| 자리 부재 경보 | 자리를 110초 비우면 100% (16:30 이후 절반 속도) | 누적 |

실험 방법

- 위 규칙으로 하루의 사건 시간표를 무작위로 생성, 주 5일을 20,000번. 직급은 대리와 과장 두 가지(고자질 주체가 다름).
- "겹침" = 두 사건의 진행 구간이 겹치는 것.

결과 표: 하루 평균 사건 수(요일별), 사건이 하나도 없는 "조용한 구간"의 평균·최장 길이(초), 두 사건 이상이 겹친 시간의 비율(%), 가장 자주 겹치는 사건 쌍 상위 5개.

판단 기준

- 창가 감시를 뺀 사건이 하루 평균 2\~4개면 적정. 5개 이상이면 피로, 1개 미만이면 심심.
- 겹친 시간이 하루의 10%를 넘으면 겹침 방지 규칙이 더 필요.
- 조용한 구간의 최장 길이가 평균 120초를 넘으면 중반이 비는 것.

## 요청 7: 아이템·쿠폰 가격 대비 효과

알고 싶은 것: 각 물건이 값어치를 하는가. 사면 무조건 이득인 물건과 아무도 안 살 물건을 찾고 싶습니다.

| 물건 | 가격 | 기한 | 효과 |
| --- | --- | --- | --- |
| 책상 화분 | 2,000 | 7일 | 의심도가 25% 더 빨리 줄어듦 |
| 모니터 가리개 | 6,000 | 5일 | 화면 딴짓(웹툰·폰·쇼핑)의 들킴 30% 감소 |
| 부장 레이더 이어폰 | 9,000 | 5일 | 부장님 접근을 미리 알림 (반응이 늦을 확률을 절반으로 가정) |
| 대리 출석 인형 | 12,000 | 5일 | 자리 부재 한도 110초 → 150초 |
| 최고급 마네킹 | 60,000 | 5일 | 자리 부재 한도 240초 |
| 에너지 드링크 | 1,500 | 1회 | 그날 복귀 시간 절반 |
| 시말서 면제권 | 50,000 | 1회 | 경고 −1 (하루 1장) |
| 부장님 출장 쿠폰 | 30,000 | 1회 | 그날 남은 시간 부장님 없음 (과장부터) |
| 반차권 | 40,000 | 1회 | 그날 업무·실적 목표 면제, 수입도 없음 |
| 수면제 커피 | 5,000 + 커피 1,000 | 1회 | 부장님이 게임 2시간(약 93초) 잠듦. 15% 확률로 실패해 의심도 +40. 깬 뒤 의심도 속도 +0.10 (대리부터) |
| 부장님께 커피 | 1,000 | 하루 1회 | 의심도 속도 −0.05 |
| 법인카드 | 무료 | 하루 1회 | 카페·식당 첫 구매 무료 (과장부터, 평균 2,000원 상당으로 가정) |

실험 방법

- 요청 1의 하루 모형에 물건 하나씩을 적용해, "물건 없을 때 대비 실수령액이 얼마나 늘어나는가"를 측정. 기한이 있는 물건은 기한 전체의 합계.
- 사원 / 대리 / 과장 / 부장 4개 직급 × 유형 4가지.
- 출장 쿠폰·수면제 커피는 사용 시각을 9:10 / 11:00 / 14:00 세 가지로.
- 시말서 면제권은 "해고를 한 번 막았을 때 아끼는 금액"(통장 잔고 + 강등으로 잃는 일수 × 하루 수입)으로 환산.

결과 표: 물건별·직급별 순이익(늘어난 실수령액 − 가격), 본전을 뽑는 데 걸리는 일수, 사는 것이 이득인 최소 직급.

판단 기준

- 순이익이 가격의 3배를 넘으면 너무 싸거나 너무 강한 것.
- 어느 직급·유형에서도 순이익이 음수면 살 이유가 없는 것.
- 출장 쿠폰을 매일 사도 이득이면 게임의 핵심 긴장(부장님 피하기)이 사라지므로 반드시 알려 주세요.

## 스튜디오를 실행할 수 있을 때

로블록스 스튜디오로 게임을 직접 돌릴 수 있다면, 계산 모형의 가정값을 실측값으로 바꾸는 것이 가장 큰 가치입니다. 계산 모형이 다루지 못하는 공간 요소(부장님 동선, 거리, 시야)를 여기서 확인합니다.

### 실행 환경

- 프로젝트는 Rojo로 관리합니다. `rojo serve salary.project.json`을 켠 뒤 스튜디오에서 Rojo 플러그인으로 연결하고 플레이(F5)합니다.
- 설정값은 `shared/SalaryConfig.luau` 한 파일에 모여 있습니다. 스튜디오에서만 동작하는 시험용 스위치가 있습니다: `TEST_RANK`(시작 직급), `TEST_MONEY`(시작 돈), `TEST_COMPANY`(회사 고정), `TEST_REVIEW`(매일 고자질·도움 요청 발생), `TEST_EVENT`(돌발 이벤트 지정), `TEST_MISSION`(긴급 프로젝트 지정).
- 측정 중에는 `TEST_REVIEW`와 `TEST_EVENT`를 꺼야 평소 빈도가 나옵니다.
- 하루가 실제 7분이라 한 주에 약 40분이 걸립니다. 반복이 많이 필요한 측정은 아래의 자동 플레이 스크립트로 돌리고, `DAY_SECONDS`는 줄이지 마세요(시간 기반 규칙의 비율이 달라집니다).

### 먼저 만들 것: 측정 기록과 자동 플레이

1. 측정 기록 스크립트 (서버, 스튜디오에서만 동작): 1초마다 게임 시각, 플레이어 상태, 의심도, 오늘의 의심도 속도, 부장님에게 보이는지 여부, 부장님과의 거리를 기록합니다. 퇴근 때 하루 요약(실적, 적발 횟수, 일한 시간, 발생한 사건 목록과 시각, 인사평가 하루 점수)을 한 줄 JSON으로 Output에 출력합니다.
2. 자동 플레이 스크립트: 사람이 조작하지 않아도 되게, 공통 전제의 플레이어 유형 4가지를 흉내 냅니다. 자리에 앉아 유형별 딴짓을 고르고, 부장님이 보이면 유형별 반응 시간 뒤에 일하는 척으로 바꿉니다. 행동 선택은 게임이 쓰는 `SetAction` 요청과 같은 경로로 넣어 주세요.
3. 두 스크립트 모두 게임 규칙을 바꾸지 않아야 합니다. 게임 코드를 고쳐야 측정이 가능한 경우에는 고친 부분을 따로 적어 주세요.

## 결과 보고 형식

요청마다 아래 순서로 답해 주세요.

1. 가정: 문서에 없어 직접 정한 값과 그 이유.
2. 결과 표: 요청에 적힌 항목 그대로. 숫자는 소수 한 자리까지.

4. 제안: 미달인 항목마다 바꿀 수치 하나와 바꾼 뒤 다시 돌린 결과. 수치를 여러 개 바꾸지 말고 가장 영향이 큰 하나만.
