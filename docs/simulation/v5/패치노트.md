# 측정 기반 v5 패치

게임 규칙·보상·복귀 시간 수치는 변경하지 않았다. 기존 v4 보고서의 C 실패 및 본 실측 0/24 결과를 유지한다. v5 기록을 v1~v4와 합산하지 않는다.

## 변경 범위

- `shared/SalarySimulation.luau:2`: 프로토콜 `v5-split-telemetry`.
- `shared/SalarySimulationLog.luau:5`: 긴 JSON을 240바이트 단위 hex 조각으로 출력. ID·순서·전체 길이 포함, 측정 모드 외 출력 금지.
- `places/salary/server/SimulationRecorder.luau:19`: 공통 로그 전송. 21행 관찰 콜백 등록, 100행 실제 상태 관측에 playerId·적발 누적 수 추가.
- `places/salary/client/SimulationAuto.client.luau:6`: 모든 측정 로그를 공통 전송기로 출력.
- `places/salary/server/Employees.luau:1149`: 기존 계산을 마친 실제 복귀 시간과 요청 시 적발 수 기록.
- `places/salary/server/Employees.luau:2915`: 아슬아슬 지급 사유·의심도·거리·시야·행동·금액·콤보·횟수·복귀 후 시간 기록. 관찰 오류는 pcall로 격리. 기존 지급 계산 유지.
- `tools/salary_simulation/studio_logs.py:10`: 순서가 뒤섞인 조각 복원, 중복·손상·누락 감지. 50행 일별 필수 기록 검사. 96행 이번 추출의 세션 목록을 저장하여 이전 출력이 재집계되지 않도록 함.
- `tools/salary_simulation/v5_check.py`: 시야→요청 / 요청→서버 work / 시야→서버 work 분리, 서버 계산 복귀 시간 대비 잔여 지연 계산, 적발 개입 제외, 보너스 지급 기록과 일일 합계 대조.
- `tools/salary_simulation/test_v5.py`: 합성 데이터 테스트 8개 추가.

Employees는 기존 게임 파일이지만 추가한 것은 측정이 켜졌을 때만 등록되는 관찰 훅 두 곳이다. 기존 사용자 변경을 되돌리지 않았고 커밋하지 않았다.

## 판단 기준

2026-11-25 사용자 정정 기준: 시야→일하기 요청 중앙값 0.5~0.8초, 요청→서버 work 시간에서 서버가 계산한 복귀 시간을 뺀 추가 지연의 중앙값 0.3초 이하. 시야→서버 work 전체 시간은 참고값이다. 개별 지연 초과만으로 실패시키지 않는다. 의도적 늦은 반응은 별도 집계하며 복귀 추가 지연에는 포함한다. 실제 상태 관측 주기는 0.1초여서 정확한 프레임 시각은 아니다. 게임 복귀 시간·규칙은 유지한다.

현재 분석은 단일 봇·단일 플레이어 세션 대상이다. 지연 반응은 별도 집계하고 적발이 개입한 전환은 제외 사유를 남긴다. 누락·파싱 오류가 있으면 통과로 처리하지 않는다.

## 패치 직후 확인 결과 (재검증 전 기록)

- Python 자동 테스트 11개 통과: 기존 3개 + 신규 8개. 테스트는 합성 데이터이며 게임 실측이 아니다.
- 일반 및 측정 Rojo 빌드 성공. 빌드 성공만으로 Luau 게임 실행을 검증했다고 보지 않는다.
- Studio 편집 모드에서 실제 전송 모듈 실행: 긴 한글·이모지 문자열을 12개 조각으로 출력, 최대 603바이트, Python에서 원문 완전 복원. 측정 비활성 상태에서는 출력 없음. 근거 `transport_smoke.log`, `transport_smoke.json`.
- 편집 모드 Workspace의 SalarySimulation 계열 속성 0개, 실행 중 아님. 근거 `cleanup.log`.
- 패치 후 게임 플레이·워크숍·자연 발생 5일 검증은 **미실행**. 실제 지급 훅과 복귀 훅의 런타임 검증은 **미확인**. 본 실측 신규 완료 0/24.
