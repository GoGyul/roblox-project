# 월급루팡 시뮬레이션 — 계산 결과와 Studio 파일럿

**상태: 계산 실험 1~7의 기본 표본 실행 완료. Studio는 아래 실제 완료 일수만 측정. 요청서의 전체 실측 분량을 완료한 보고서가 아닙니다.**

## 먼저 읽을 가정과 한계

- 아래 계산 표는 요청서 규칙의 결과입니다. 현재 게임과 동일한 구현이라고 주장하지 않습니다. 기본 난수 씨앗은 20261125이며 전체 설정은 `results/config.json`, 상세 가정은 `results/assumptions.json`입니다.
- 시야 방문은 8초 고정, 방문 사이 간격은 지수분포입니다. 최초 상태를 정상상태 확률로 시작하며 점심에는 시야를 끕니다. 행동은 8초마다 선택하고 반응은 0.5초에 복귀 시간과 지연을 더합니다.
- 시작 업무 할당량을 먼저 일합니다. 현재 게임은 자리에서 딴짓해도 업무 시간이 차므로 모형의 업무 충족 검사도 모든 착석 시간을 셉니다. 복귀 중 수입, 거리, 강제 방문, 이벤트 감봉 등은 실제 게임과 다릅니다.
- 수다 0~3회와 프로젝트 보너스에는 이동·대화 시간을 차감하지 않았습니다. 따라서 수입은 낙관적일 수 있습니다. 좋은 맞장구는 60%, 주제당 3번입니다.
- Q2의 도달 시간은 400일 내 도달자만의 평균입니다. 도달률과 미도달 인원을 반드시 함께 보세요. 초기 정체는 400일 내 대리 미도달이면서 초반 해고 2회 이상인 비율로 정의했습니다.
- Q3는 해고일을 포함한 일별 수입 분포를 5번 추출하는 가상 주간 평가입니다. 실제 해고자의 평가 제외·복직 흐름은 구현하지 않았습니다. 동점은 더 나쁜 순위를 줍니다.
- Q4는 수다 2/4/6명 × 선물 1/2/4회 전 조합입니다. 집중 전략의 남는 횟수는 쓰지 않으며 동일 NPC의 하루 한도를 지킵니다. 도달일은 집중 대상 전원이 기준을 넘은 날입니다. 선물 비용·왕복 시간은 제외했습니다.
- Q5는 대리 고정, 프로젝트·목표 미달 등 추가 경고 없이 적발만 누적합니다. 한 번 해고되면 해당 주의 후속 위험집단에서 제외하며 표의 n은 그날 살아 있는 인원입니다.
- Q6는 창가 감시를 점심에도 포함합니다. 기본 전략에 화상회의·외출이 없어 화상 질문과 부재 경보는 0으로 두었습니다. 회식은 근무시간 밖이므로 제외합니다. 이벤트는 허용 구간 내 균등 시작, 퇴근 이후 부분은 잘랐습니다.
- Q7은 동일 씨앗의 하루 모형 차이를 기한만큼 곱한 기대효과입니다. 출석 인형/마네킹은 착석 전략에서 효과 0이며 외출 전략 가치는 미측정입니다. 면제권은 별도 조건부 복구 실험을 제공합니다.

## Studio에서 직접 확인한 결과

실행은 저장을 막는 Studio 전용 모드, 실제 420초/일로 진행했습니다. 전략은 보통→조심→욕심→초보→보통 순입니다. 요일·이벤트·누적 경고·승진이 바뀌므로 전략 간 우열을 단정할 수 없습니다. 실제 `SetAction` RemoteEvent를 이용했습니다. 서버 물리·이벤트 난수는 고정하지 않았으며 Python과 클라이언트 선택만 고정 씨앗을 사용합니다.

**환경 발견:** TEST_EVENT가 빈 문자열이어도 기존 Studio 분기는 감사→정전→생일→소방훈련→워크숍을 강제 순환했습니다. 이번 5일은 이벤트 대응 파일럿이며 자연 발생률 표본이 아닙니다. 다음 실측부터 서비스의 이벤트 선택·시작 시각 분기를 사용하도록 측정 모드를 수정했습니다. 진행 중이던 실행에 소급 적용하지 않았습니다.

**봇 한계:** 다섯째 날 워크숍이 플레이어를 이동시킨 뒤 초기 봇이 자리에 돌아오지 못했습니다. 다섯째 날은 보통형 수입 비교에서 제외하고 연속 실행·미착석 결과만 보존합니다. 넷째 날 적발 1회는 의심도 누적이 아니라 소방훈련에 대피하지 않아 받은 적발입니다.

다섯째 날 최종 통장 0원·경험치 6,000·주임→사원 강등을 확인했습니다. 이후 v2 측정 모드로 별도 재실행하여 첫날 강제 감사가 발생하지 않는 것을 확인했습니다. 걷기·일반 착석 프롬프트를 사용하는 자동 복귀 코드를 추가했지만, 재검증 중 자리 이탈이 관측되지 않아 워크숍 복귀 성공은 아직 미검증입니다. 짧은 재실행은 하루 수입 비교에 포함하지 않았습니다. 근거: [재검증 기록](studio/validation.json). 종료 후 편집 모드의 SalarySimulation 속성을 제거했습니다.

실제 게임은 승진 시 경고를 초기화합니다. 셋째 날 주임 승진에서 2→0을 관측했고 서버 코드에서도 확인했습니다. 또한 프로젝트는 시간대를 매일 예약하며 문서의 40% 확률 게이트가 없습니다. 퇴근 임박·부장 출장·사무실 밖 조건으로 취소될 수 있고 점심·공통 이벤트 중 타이머가 정지합니다. 제한 시간도 현재 100~110초로 문서의 60~90초와 다릅니다.

## 민감도와 재현

수입의 시야 비율·반응 지연·보너스 규모를 각각 ±30% 바꾼 표는 `results/sensitivity_income.csv`입니다. 각 변경은 독립적으로 적용합니다. 승진(보통형 무소비), 평가(전체), 위험(전체), 물건(전체)의 같은 가정 민감도는 `results/sensitivity/`에 있습니다. 위험의 세 번째 가정은 보너스가 아니라 방문 지속 시간입니다. 친밀도는 선물·좋은 맞장구·도움 요청 확률, 사건은 지속 시간·감시 간격·프로젝트 확률을 각각 ±30% 변경합니다.

실행 명령:

```sh
arch -x86_64 /usr/bin/python3 tools/salary_simulation/run.py
arch -x86_64 /usr/bin/python3 -m tools.salary_simulation.experiments
arch -x86_64 /usr/bin/python3 -m tools.salary_simulation.reruns
arch -x86_64 /usr/bin/python3 -m tools.salary_simulation.sensitivity
arch -x86_64 /usr/bin/python3 -m tools.salary_simulation.source_rules
arch -x86_64 /usr/bin/python3 -m tools.salary_simulation.coupons
arch -x86_64 /usr/bin/python3 -m unittest tools.salary_simulation.test_model -v
python3 tools/salary_simulation/studio_logs.py
python3 tools/salary_simulation/report.py
```

Intel NumPy가 설치된 이 Mac에서 사용하는 실행 방식입니다. 다른 환경에서는 NumPy 설치 후 `python3`로 실행하면 됩니다. `--smoke`는 표본 50개 검사용이며 기본 결과와 다른 출력 폴더를 지정하세요.

Studio 전용 진입점은 `salary.simulation.project.json`입니다. `shared/SalarySimulation.luau`에서 시작 직급·회사·전략 배열·일수를 바꿉니다. `SalarySimulation` Workspace 속성과 `RunService:IsStudio()`가 모두 참일 때만 자동 플레이·저장 차단·측정이 켜집니다. 실제 게임의 하루 길이·급여·경고 규칙은 측정을 위해 변경하지 않았습니다.
